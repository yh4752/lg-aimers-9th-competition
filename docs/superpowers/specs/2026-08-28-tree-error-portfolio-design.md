# 실패 유형·이종 잔차 포트폴리오 설계

## 1. 목적과 현재 기준선

현재 제출 기준선은 `c1_anchor_residual` CatBoost 3시드 모델이며 Public Score는
`977.3809532715`다. 다음 실험은 이미 거절된 R/F 전문가와 계층 보정을 반복하지
않고, 기준선과 오류 원인이 다른 두 축을 순서대로 검증한다.

1. 공식 학습 데이터에서 복원 가능한 실패 유형에 집중한 CatBoost 잔차 전문가
2. XGBoost·LightGBM 이종 잔차 모델

두 축은 서로 독립 후보다. 한 축이 거절되어도 다른 축은 계속 실행할 수 있으며,
둘 다 통과했을 때만 마지막 결합 후보를 평가한다. 기존 977점 제출물과 E2 모델
delivery는 수정하지 않는다.

## 2. 실행 예산과 단계

전체 예산은 Kaggle T4 두 장 기준 최대 15시간으로 제한한다. 하나의 15시간짜리
실행으로 묶지 않고 다음 단계별 handoff를 남긴다.

| 단계 | 작업 | 최대 시간 | 가속기 |
|---|---|---:|---|
| S0 | 실패 유형 라벨 감사 | 30분 | CPU |
| S1 | 실패 유형 잔차 전문가 구조 선별 | 4시간 | T4 x2 |
| S2 | S1 통과 구조의 3시드 확인 | 3시간 | T4 x2 |
| S3 | XGBoost·LightGBM 잔차 후보 | 5시간 | T4 x2 및 CPU |
| S4 | 통과 후보 결합, full fit, 규칙 감사 | 2시간 30분 | T4 x2 |

각 단계는 검증된 handoff ZIP 하나만 `/kaggle/working`에 게시한다. 중단 후에는
가장 최근 handoff 하나만 입력으로 연결한다. 같은 계열의 이전 handoff를 둘 이상
연결하면 입력 검증에서 중단한다.

## 3. 공통 데이터와 시간 검증

모든 후보는 E2에서 확정한 행 독립 피처와 기준선 OOF 예측을 사용한다. 시간 fold는
`2021→2022`, `2022→2023`, `2023→2024`로 고정한다. fold의 학습 통계, 실패
라벨과 모델은 검증 연도보다 앞선 행만 사용한다.

평가 행 추론에는 현재 행의 원본 변수, 현재 행에서 만든 파생 변수, 공식 학습
데이터로 미리 고정한 상태와 학습 모델만 사용한다. 평가 데이터 전체의 평균,
빈도, 순위, rolling, 같은 선수의 평가 행 집계와 추론 순서는 사용하지 않는다.

기준선 확률을 `p0`, 정답을 `y`라고 할 때 추가 모델의 학습 목표는
`r = y - p0`인 잔차다. 최종 확률은 고정된 OOF 선택 계수 `a`를 사용해
`clip(p0 + a * r_hat, 1e-5, 1 - 1e-5)`로 계산한다. 평가 데이터에서 계수를 다시
선택하지 않는다.

## 4. S0: 실패 유형 라벨 감사

기존 `KAGGLE_FAILURE_AUDIT_CELL.py`를 그대로 사용한다. `middle`, `reverse`,
`other_failure`를 각 cutoff 안에서 누적 통계의 다음 변화량으로 복원하고 다음
조건을 모두 만족한 유형만 S1 후보로 전달한다.

- 원본 행 대비 라벨 coverage `>= 0.98`
- 변화량 이진 복원률 `>= 0.999`
- 복원 success와 공식 target 일치율 `>= 0.999`
- middle/reverse 동시 양성률 `<= 0.001`
- A1~A4 각각 양성 및 음성 행 `>= 5,000`

감사는 review-only다. 평가 데이터, 모델 학습과 제출 파일을 다루지 않는다. 통과한
유형이 하나도 없으면 S1과 S2를 생략하고 S3로 이동한다.

## 5. S1: 실패 유형 잔차 전문가 구조 선별

S0를 통과한 유형마다 CatBoost 잔차 전문가 하나를 만든다. 전문가의 입력은 E2의
행 독립 피처이고 target은 `y - p0`다. 해당 실패 유형 행의 학습 가중치를 높여
그 상황의 오류를 더 강하게 학습하되, 다른 행도 남겨 전체 확률이 무너지지 않게
한다.

구조 탐색은 시드 3407 하나만 사용한다. 유형별 가중 배수는 `2.0`, `4.0` 두 개,
잔차 적용 계수는 `0.05`, `0.10`, `0.15` 세 개로 제한한다. 각 유형은 독립적으로
판정하며 한 유형의 실패가 다른 유형을 막지 않는다. 여러 유형이 통과하면 OOF에서
가장 좋은 단일 전문가와 통과 전문가의 단순 합성만 비교한다. 계수 조합의 전수
탐색은 하지 않는다.

S1 수용 기준은 다음과 같다.

- 전체 weighted Brier gain `>= 0.00008`
- 세 fold 중 두 fold 이상 개선
- `2023→2024` fold gain `>= 0`
- 표본 5,000개 이상 주요 구간의 최대 악화 `<= 0.00030`
- bootstrap gain 하한 95% `> 0`
- NaN, infinity, 확률 범위 및 row alignment 위반 없음

## 6. S2: 실패 전문가 다중 시드 확인

S1에서 수용된 하나의 구조에만 시드 42와 2026을 추가한다. 세 시드 확률을 단순
산술 평균하며 시드별 가중치는 최적화하지 않는다.

S2는 S1 공통 gate를 다시 통과해야 하고, 각 fold에서 세 시드 중 적어도 두 시드가
기준선보다 나쁘지 않아야 한다. 이 조건을 통과하지 못하면 실패 전문가 계열은
거절하고 S3로 이동한다.

## 7. S3: XGBoost·LightGBM 이종 잔차 후보

XGBoost와 LightGBM은 동일한 E2 피처와 잔차 target을 사용하되 각 라이브러리당
고정 구조 하나만 학습한다. 구조 탐색은 시드 3407과 세 시간 fold로 수행한다.
각 모델의 잔차를 기준선에 더하는 계수는 `0.05`, `0.10`, `0.15`만 비교한다.

두 모델은 각각 단독 판정한다. 둘 다 통과하면 두 잔차를 같은 비중으로 합친 후보를
추가로 평가하되 이종 모델의 총 계수는 `0.15`를 넘지 않는다. CatBoost 기준선과
예측이 사실상 같거나 잔차 상관이 `0.995` 이상이면 다양성이 없는 것으로 기록하고
거절한다.

S3 수용 기준은 다음과 같다.

- 전체 weighted Brier gain `>= 0.00005`
- 어느 fold도 `-0.00003`보다 크게 악화되지 않음
- `2023→2024` fold gain `>= 0`
- 표본 5,000개 이상 주요 구간의 최대 악화 `<= 0.00030`
- bootstrap gain 하한 95% `> 0`
- 기준선 잔차와 상관 `< 0.995`

통과한 구조만 시드 42와 2026을 추가해 3시드 평균으로 다시 같은 gate를 확인한다.

## 8. S4: 최종 선택과 full fit

S2와 S3에서 통과한 후보만 최종 비교한다.

- 하나만 통과하면 그 후보를 선택한다.
- 둘 이상 통과하면 각 단일 후보와 고정 동일비중 결합 후보를 비교한다.
- 결합 후보는 가장 좋은 단일 후보보다 weighted Brier를 `0.00002` 이상 추가로
  개선해야 채택한다. 그렇지 않으면 더 단순한 단일 후보를 선택한다.
- 어떤 후보도 통과하지 못하면 기존 977점 기준선을 유지하고 캠페인을 종료한다.

선택된 후보만 2019~2024 공식 학습 데이터로 full fit한다. OOF에서 정한 피처,
시드, 학습 반복 수와 계수를 그대로 사용한다. full fit 이후에는 모델 파일,
피처 상태, 기준선 delivery, 결정 파일의 해시를 묶은 candidate delivery만 만든다.
이 delivery는 아직 제출 ZIP이 아니다.

## 9. 산출물과 재개

각 handoff는 다음을 포함한다.

- 원자적으로 기록한 campaign state
- 완료 job의 모델, OOF 예측, 지표와 worker log
- 후보별 gate 결정과 탈락 사유
- 현재 코드·계약·공식 데이터·기준선 입력 해시
- review ZIP과 resume ZIP
- 수용된 경우에만 candidate delivery

진행 중 snapshot은 최소 15분 간격으로 같은 고정 파일을 교체하며 브라우저 자동
다운로드를 반복하지 않는다. 정상 완료 또는 오류 시에만 최종 handoff 하나를
다운로드한다. 완료된 job은 정확한 bindings와 checkpoint 검증을 통과해야만 재사용한다.

## 10. 제출 및 규칙 gate

candidate delivery가 생겨도 바로 제출 패키지를 만들지 않는다. 다음 조건을 모두
통과한 뒤 별도 패키징 단계에서만 제출 ZIP 생성을 허용한다.

- 후보 상태 `accepted`
- acceptance, 모델, 피처 상태, 코드와 계약의 현재 해시 일치
- singleton, shuffle, reverse, companion, batch-size 행 독립성 검사 통과
- 공식 5행 smoke inference 성공
- 추론 10분 및 RAM 28GB 제한 충족
- 네트워크, 외부 프로세스, 평가 데이터 기반 통계 및 순서 의존성 없음
- 공식 제출 구조와 requirements 정적 검사 통과

Public 점수는 후보 선택이나 계수 조정에 사용하지 않고, 모든 내부 gate가 끝난
후의 외부 확인값으로만 기록한다.

## 11. 완료 조건

기술적 완료는 각 단계의 중단·재개, 입력 identity, 결과 ZIP 검증과 행 독립성 검사가
통과하는 것이다. 실험적 완료는 최소 하나의 독립 후보가 고정 OOF gate를 통과하는
것이다. 모든 후보가 탈락해도 그 결과를 정상 종료로 기록하며 기존 977점 제출물을
덮어쓰지 않는다.
