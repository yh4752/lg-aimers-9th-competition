# 성능 우선 실험 사전 확인 설계

## 목적

모든 새 ML·DL 실험에서 비용·시간·smoke 결과 때문에 탐색 규모가 다시 보수적으로
축소되는 것을 막는다. 대화 기억이나 모델별 숫자 하한에 의존하지 않고, 새 대회
저장소의 기존 작업 지침과 실행 계약에 짧은 필수 확인 절차를 둔다.

## 적용 경계

이 규칙은 `lg-aimers-9th-competition` 저장소 안에서 설계·구현하는 모든 새 대회
실험에 적용한다. 앞으로 새 대회 실험은 이 저장소에서 시작한다. 다른 저장소와
임시 코드까지 제어하는 전역 스킬은 만들지 않는다.

## 필수 사전 확인

실험 설계를 제안하기 전에 다음 네 항목을 확인해 사용자에게 표시한다.

```text
[성능 우선 확인]

1. smoke 결과를 성능 근거로 사용하지 않았는가?
2. 첫 본 실험에 큰 모델·긴 학습·넓은 탐색이 포함됐는가?
3. 최고 설정이 탐색 경계에 있으면 다음 범위를 확장하는가?
4. OOM·시간·비용 또는 단일 설정 실패를 후보 계열 종료 근거로 쓰지 않는가?
```

하나라도 충족하지 않으면 실험 설계는 미완성이다. 이 확인은 특정 architecture,
depth, epoch 또는 탐색 상한을 고정하지 않는다. 모델과 데이터에 맞는 큰 설정을
본 실험에 포함하고, 경계에서 개선이 이어지면 다음 라운드에서 범위를 확장하는
절차를 고정한다.

## 실행 의미

- smoke는 import, CUDA, 데이터 흐름과 출력 형태의 기술 확인 전용이다.
- 첫 본 실험은 성능을 판단할 수 있는 충분한 모델 규모·학습 시간·탐색 폭을
  포함한다.
- 최선 결과가 width, depth, leaves, epoch 또는 다른 탐색 경계에 있으면 그 값을
  최종 상한으로 취급하지 않고 다음 범위를 확장한다.
- OOM은 batch size, mixed precision, gradient accumulation과 필요 시 checkpoint
  재시작으로 대응한다. OOM 자체는 모델 계열 기각 근거가 아니다.
- 비용과 실행 시간은 사용자 안내와 실행 순서를 정하는 정보다.
- 한 seed, 한 설정, 한 residual 또는 한 feature view 실패는 해당 설정만 종료한다.

## 저장소 변경

- `AGENTS.md`: 네 항목의 사전 확인과 미충족 시 설계 미완성 규칙을 추가한다.
- `docs/EXPERIMENT_CONTRACT.md`: smoke, 본 실험, 경계 확장, OOM 재시도와 단일
  실패의 실행 의미를 추가한다.
- `tests/test_repository_contract.py`: 두 문서의 핵심 의미가 삭제되면 실패하는
  계약 테스트 하나를 추가한다.

## 명시적 제외

- 새 상태 JSON, 체크리스트 파일 또는 자동화 시스템
- 별도 CLI gate와 config schema
- 전역 개인 스킬과 기존 저장소 수정
- 모델별 고정 depth·width·epoch 하한
- `docs/ROADMAP.md`, 노트북, 모델 코드와 제출 패키지 변경

## 검증 기준

- 새 테스트가 먼저 실패하고 문서 변경 후 통과한다.
- 기존 저장소 테스트가 모두 통과한다.
- 변경 범위는 승인된 세 파일로 제한된다.
- 규칙은 ML과 DL 모두에 적용되며 비용·OOM·단일 실패로 계열을 닫지 않는다.
