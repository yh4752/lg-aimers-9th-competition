# R/F 경기 유형 전문가 실험 설계

## 1. 목적과 범위

현재 제출 기준선은 Public Score `977.3809532715`를 기록한
`c1_anchor_residual` CatBoost 3시드 모델이다. 시간 이중 모델 Stage T3는
세 fold 가중 Brier와 구간 안정성 기준을 통과하지 못했으므로 이 실험의
입력이나 기준선으로 사용하지 않는다.

이번 실험은 현재 행의 `game_type`이 `R`인지 `F`인지에 따라 별도의
CatBoost 전문가를 적용했을 때 기존 기준선의 OOF 오차를 안정적으로 줄일 수
있는지 확인한다. 효과가 검증되지 않은 실패 유형 전문가, 이종 모델, 추가
후처리는 범위에서 제외한다.

실험 결과는 다음 셋 중 하나로 끝난다.

- `rejected`: 검증 기준을 통과하지 못해 제출 후보를 만들지 않는다.
- `accepted`: 검증을 통과해 전체 학습 데이터로 만든 delivery를 남긴다.
- `paused`: 실행 제한시간 전에 안전하게 중단하고 재개 가능한 resume을 남긴다.

## 2. 고정 기준선과 입력

- 기준 모델: E2 `c1_anchor_residual`
- 기준 모델 구성: 동일 CatBoost 구조의 시드 `42`, `2026`, `3407` 평균
- 시간 fold: `2021→2022`, `2022→2023`, `2023→2024`
- 구조 선택 시드: `3407`
- 최종 확인 시드: `42`, `2026`, `3407`
- 실행 환경: Kaggle T4 GPU 2장
- 최대 실험 시간: 5시간 30분
- 종료 여유: Kaggle 제한 대비 최소 30분

사용자 입력은 공식 대회 데이터셋과 로컬에서 준비한 단일 통합 실험
데이터셋으로 제한한다. 통합 데이터셋에는 E2 기준선의 검증 근거와 필요한
모델 상태를 포함하되 공식 원본 데이터는 중복 포함하지 않는다. 압축 파일과
Kaggle에서 자동으로 풀린 디렉터리를 모두 찾을 수 있어야 하며, 동일 종류의
입력이 둘 이상 발견되면 임의 선택하지 않고 학습 전에 중단한다.

## 3. 모델 구조

E2 기준선은 수정하지 않는다. 각 시간 fold에서 다음 세 전문가를 독립적으로
학습한다.

- `F-small`: F 경기만 사용하고 정규화를 강화한 소용량 전문가
- `F-wide`: F 경기만 사용하고 표현력을 조금 높인 전문가
- `R-expert`: R 경기만 사용한 전문가

공통 CatBoost 설정은 E2와 같은 learning rate `0.04`, Bayesian bootstrap,
border count `128`, CTR complexity `2`, early-stopping wait `60`을 사용한다.
구조 차이는 다음으로 고정한다.

| 전문가 | iterations | depth | l2 | random strength | bagging temperature |
| --- | ---: | ---: | ---: | ---: | ---: |
| `F-small` | 800 | 6 | 10.0 | 1.0 | 1.0 |
| `F-wide` | 800 | 8 | 8.0 | 0.75 | 0.75 |
| `R-expert` | 800 | 8 | 5.0 | 0.5 | 0.5 |

F 모델 두 개는 작은 F 표본에서 깊은 범주형 상호작용이 필요한 경우와 강한
정규화가 필요한 경우를 구분하기 위한 최소 비교다. R 모델은 기존 c1과 같은
용량을 사용해 `R 행만 학습한다`는 변화만 검증한다.

전문가는 E2 모델이 자신을 학습한 행에 낸 예측의 잔차를 사용하지 않는다.
그 방식은 별도의 cross-fitting 없이는 과적합된 residual target을 만들 수
있기 때문이다. 대신 기존 c1과 같은 방식으로 fold의 과거 학습 데이터에서
만든 anchor 잔차를 학습한다.

검증 행의 최종 확률은 다음과 같이 계산한다.

```text
expert_probability = clip(anchor + predicted_anchor_residual, eps, 1 - eps)
final_probability = (1 - alpha) * baseline_probability
                    + alpha * expert_probability
```

`F-only` 후보는 F 행에만 F 전문가를 적용하고 R 행은 기준선 확률을 그대로
사용한다. `R/F` 후보는 두 구간 모두 해당 전문가를 적용한다. R과 F의 표본
수와 전문가 신뢰도가 다르므로 `alpha_R`과 `alpha_F`를 독립적으로 둔다.
각 비율은 `0.25`, `0.50`, `0.75`, `1.00`만 비교한다. `F-only`는
`alpha_R=0`으로 정의한다. 이 조합 탐색은 저장된 OOF 예측만 사용하므로 모델
학습량을 늘리지 않는다. 평가 데이터의 R/F 비율이나 결과를 보고 비율을 다시
조정하지 않는다.

## 4. 선택과 확인 절차

### 4.1 구조 선별

시드 `3407` 하나로 세 전문가와 세 시간 fold를 학습한다. 총 9개 작업이며
T4 두 장에 한 작업씩 배치한다. `F-small`과 `F-wide` 중 하나를 고르고,
`F-only`와 `R/F` 조합 및 혼합 비율을 비교한다.

구조와 구간별 혼합 비율은 `2021→2022`, `2022→2023` fold만 사용해 결정한다.
`2023→2024` fold는 선택 과정에서 보지 않고 고정된 후보의 최근 시즌 확인에
사용한다. 동률이면 더 작은 모델, `alpha_R + alpha_F`가 더 작은 조합,
`F-only` 순으로 선택해 불필요한 복잡도를 피한다.

전문가 하나가 앞선 두 fold 모두에서 해당 구간 기준선을 악화시키면 그
전문가는 즉시 탈락시키고 추가 시드를 학습하지 않는다. R과 F가 모두
탈락하면 실험을 `rejected`로 끝낸다.

### 4.2 다중 시드 확인

구조 선별을 통과한 전문가만 시드 `42`, `2026`을 추가한다. 기존 시드
`3407`과 합쳐 3시드 평균 OOF 예측을 만들고, 구조 선택 때 고정한 전문가
조합과 `alpha_R`, `alpha_F`를 그대로 적용한다. 최근 fold의 결과를 보고 구조나 혼합
비율을 바꾸지 않는다.

### 4.3 최종 학습

3시드 OOF 수용 기준을 모두 통과한 경우에만 공식 전체 학습 데이터로 최종
전문가를 학습한다. 최종 모델은 E2 기준 모델과 함께 사용할 수 있는 delivery
형태로 저장한다. 검증이 탈락한 경우 full-fit과 제출 패키징은 수행하지 않는다.

## 5. 수용 기준

다음 조건을 모두 만족해야 `accepted`로 판정한다.

- 세 fold 전체의 행 수 가중 Brier가 기준선보다 `0.00010` 이상 개선된다.
- 세 fold 중 적어도 두 fold에서 전체 Brier가 개선된다.
- R과 F 각각의 전체 구간 Brier 악화가 `0.00010`을 넘지 않는다.
- `2023→2024` fold의 F 구간 Brier가 개선된다.
- singleton, shuffle, reverse, companion, 여러 batch size 감사에서 동일 행의
  예측 차이가 `1e-6` 이하이다.
- 최종 확률에 NaN, infinity 또는 `[0, 1]` 범위 위반이 없다.
- 코드, 계약, 데이터, 기준 모델 및 결과물 해시가 현재 실행과 일치한다.

구조 선별 중 사용한 첫 두 fold의 양수 개선만으로는 수용하지 않는다. Public
리더보드 점수도 후보 선택이나 수용 기준에 사용하지 않는다.

## 6. 평가 데이터 독립성

평가 시 한 행의 예측에는 다음 정보만 사용할 수 있다.

- 현재 행의 원본 값과 행 내부 파생변수
- 현재 행의 `game_type`
- 공식 학습 데이터로 미리 계산하고 저장한 통계
- 공식 학습 데이터로 학습한 모델
- OOF에서 고정한 전문가 구성과 혼합 비율

평가 데이터의 전체 평균, 빈도, 순위, 선수별 평가 행 집계, rolling, lag,
누적값은 사용하지 않는다. 평가 데이터에 등장한 R/F 비중, 선수 수, 예측
분포에 따라 모델 또는 가중치를 바꾸지 않는다. 행 순서와 batch 구성이
달라도 동일한 행은 같은 확률을 반환해야 한다.

## 7. 실행 로그와 재개

다음 이벤트를 사람이 읽을 수 있는 단일 로그에 남긴다.

- 코드·입력·GPU 확인
- 선택한 stage와 남은 벽시계 시간
- 작업 시작, 재사용, 완료, 실패
- epoch, batch, 현재 Brier, best Brier, 예상 잔여시간
- 전문가별 fold 결과와 수용 결정
- resume, review, delivery 경로와 SHA-256

각 작업 완료 시 체크포인트와 예측을 임시 경로에 쓴 뒤 원자적으로
확정한다. snapshot은 확정된 파일만 포함하며 `.tmp` 파일을 읽지 않는다.
resume의 코드·입력·계약 해시가 현재 실행과 다르면 처음부터 조용히
재학습하지 않고 명시적인 identity 오류로 중단한다.

GPU가 없거나 입력이 잘못됐으면 학습 전에 중단한다. 제한시간에 접근하면
현재 안전 경계에서 작업을 멈추고 마지막 검증 상태로 resume을 만든다.
완료한 작업은 재실행 시 `JOB_REUSED`로 표시하고, 미완료 작업만 이어서
실행한다.

브라우저 다운로드는 정상 완료, 안전 중단 또는 오류 시점에 마지막으로
검증된 resume 하나만 요청한다. 정상 완료 시 review를 추가로 요청하고,
후보가 수용된 경우에만 delivery도 요청한다. 학습 중 주기적으로 여러 ZIP을
자동 다운로드하지 않는다.

## 8. 산출물과 제출 경계

- `review`: fold·구간별 Brier, 기준선 대비 gain, calibration, 선택 근거,
  독립성 감사, 로그 및 manifest
- `resume`: 완료 작업, 체크포인트, OOF 예측, 선택 상태 및 해시 결속
- `delivery`: 수용된 최종 모델, 고정 혼합 설정, 추론에 필요한 학습 통계와
  manifest

Kaggle 실험 셀은 DACON 제출 ZIP을 만들지 않는다. 사용자가 `accepted`
delivery를 전달하면 Codex가 수용 근거와 현재 artifact 해시를 다시 검증한다.
그 검증까지 통과한 뒤 별도의 구현 단계에서 공식 제출 구조, 5행 샘플 실행,
CPU 추론 시간, 메모리, 행 독립성 및 오프라인 설치 조건을 확인하고 제출 ZIP을
만든다.

## 9. 코드 검증 범위

Codex는 전체 데이터나 GPU 학습을 실행하지 않고 다음 검사를 수행한다.

- 작은 합성 데이터에서 R/F 라우팅과 혼합식 검사
- fold별 학습 범위와 통계 누수 방지 검사
- 압축·디렉터리 입력 탐색, 중복 탐지, 경로 안전성 검사
- artifact 멤버 해시와 identity 결속 검사
- 작업 완료 직전 중단 및 resume 재개 검사
- 임시 파일과 snapshot 경합 회귀 검사
- 행 독립성 감사의 양성·음성 fixture 검사
- Kaggle 단일 셀의 문법, 크기, 내장 runtime 해시 검사
- 기존 E2와 T3 관련 회귀 검사

전체 데이터 학습과 Kaggle GPU 실행은 사용자가 수행한다. 실행 전에는 목적,
필요 입력, 예상 시간, 재실행 방법, 결과 파일과 반환해야 할 정확한 로그를 한
번에 안내한다.

## 10. 완료 조건

구현은 다음 상태가 모두 충족됐을 때 Kaggle 실행 준비가 완료된 것으로 본다.

- 통합 입력 생성 도구와 한 셀 실행 코드가 현재 계약 해시로 고정돼 있다.
- 작은 자동 검사가 모두 통과한다.
- 기존 E2/T3 동작을 깨뜨리지 않는다.
- Kaggle 셀의 시작·성공·중단·오류 로그가 명확하다.
- 재실행 시 완료 작업을 건너뛰는 것이 fixture로 검증된다.
- 제출물 생성 경로가 수용 전에는 차단돼 있다.
