# OOF 리셋 감사 설계

## 배경

규칙을 지킨 첫 TabM 제출은 Public `872.3920184667`을 기록했지만, 이후 seed
앙상블, 행 단위 파생변수, CatBoost 블렌드와 계층형 TabM 후보는 기준 모델을
안정적으로 이기지 못했다. 개별 후보를 더 추가하기 전에 실험 체계 자체를 점검해야
한다.

공식 평가지표와 내부 Brier Score는 일치한다. 문제는 지표 선택보다 서로 다른
프로토콜의 결과를 한 계보처럼 해석한 점, 두 시간 전이에서 순위가 크게 달라지는 점,
그리고 TabM 주변의 작은 변화에 후속 자원을 집중한 점에 있다.

이번 감사는 새 모델을 학습하지 않는다. 기존 OOF 산출물을 동일 행 기준으로 다시
정렬하고, 다음 GPU 실험이 필요한지부터 결정한다.

## 목표

기존 규칙 준수 모델과 격리된 과거 XGBoost 진단 자료를 읽어 다음 질문에 답한다.

1. 어떤 모델 비교가 동일한 행과 정답을 사용해 통계적으로 유효한가?
2. 모델 순위가 시간 전이, 월과 사전 지정 구간에서 얼마나 달라지는가?
3. 모델 간 예측 오차가 달라 실제 블렌딩 가치가 있는가?
4. 현재 정체의 주원인이 과소적합, 보정 실패, 시간 변화 또는 검증 불일치 중
   무엇인가?
5. 다음 GPU 실험은 최근 시즌 가중 학습, 시간 교차검증 블렌드 또는 중단 중 어느
   하나여야 하는가?

## 검토한 접근

### 채택: 기존 OOF 감사 후 필요한 증거만 보충

먼저 기존 ZIP의 OOF를 비교한다. 행 집합이나 fold가 다른 결과는 직접 순위에서
제외하고 별도 진단으로 남긴다. 감사 결과만으로 다음 방향을 고를 수 없다면, 결정에
필요한 OOF 하나만 별도 실험으로 요청한다.

이 접근은 이미 지불한 학습 비용을 활용하면서도 불완전한 비교를 숨기지 않는다.

### 기각: 기존 보고서 수치만 모아 순위 지정

보고서에 기록된 Brier는 fold, 행 집합과 전처리가 다를 수 있다. 같은 표에 옮기는
것만으로는 모델 우열이나 블렌딩 가치를 판단할 수 없다.

### 보류: 모든 모델의 통합 재학습

동일한 프로토콜로 전부 재학습하면 비교는 깨끗하지만 GPU 비용이 크다. 기존 OOF
감사에서 필요한 모델과 fold가 확인된 뒤에만 제한적으로 사용한다.

## 감사 대상과 신뢰 등급

### 규칙 준수 대상

- Stage C TabM seed별 OOF와 seed 3407 기준 모델
- 승인된 행 단위 파생변수 후보의 OOF
- 규칙 준수 CatBoost OOF와 고정 블렌드 증거
- 계층형 TabM H1, H2, H3 OOF
- 추가로 입력된 규칙 준수 산출물 중 행과 provenance를 검증할 수 있는 결과

### 격리 진단 대상

과거 XGBoost는 `QUARANTINED_DIAGNOSTIC`으로 표시한다. 원본 시간 OOF가 있고
행과 정답을 검증할 수 있을 때만 분석한다. 평가 분포 평균 이동 보정, 평가 예측,
Public에 맞춘 계수는 읽거나 재사용하지 않는다.

격리 결과는 다음 용도로만 쓴다.

- TabM과 다른 순위·잔차 패턴 확인
- 새 규칙 준수 모델 계열을 다시 검증할 가치 판단

격리 결과를 블렌드 후보, 최종 후보, 추론 코드 또는 제출 패키지로 승격하는 경로는
만들지 않는다.

## 입력 계약

감사 실행기는 ZIP 경로 목록을 받는다. 파일 이름으로 역할을 추측하지 않고 각
산출물의 manifest, state와 prediction member를 검증해 역할을 판별한다.

각 예측 자료에는 최소한 다음 값이 있어야 한다.

- 모델과 후보 ID
- fold의 학습·검증 시즌
- `row_id`
- 이진 정답
- `[0, 1]` 범위의 유한한 예측 확률
- 원본 산출물 SHA-256과 내부 예측 SHA-256
- 규칙 준수 또는 격리 진단 등급

동일 모델·fold·row ID가 서로 다른 확률이나 정답으로 중복되면 전체 감사를
중단한다. 누락된 산출물은 실패로 위장하지 않고 `missing_evidence`에 기록한다.

## 비교 가능성 규칙

직접 비교는 두 예측 자료의 fold, `row_id` 집합과 정답이 정확히 같을 때만 허용한다.
행 순서는 `row_id`로 다시 맞춘다. 교집합만 잘라 임의로 비교하지 않는다.

프로토콜이 다른 결과는 다음처럼 분리한다.

- `paired`: 같은 fold, 같은 전체 행, 같은 정답
- `descriptive_only`: 자체 지표는 계산할 수 있지만 직접 차이는 계산하지 않음
- `quarantined_diagnostic`: 규칙상 재사용할 수 없는 과거 진단
- `missing_evidence`: 필요한 예측 또는 provenance가 없음

모든 표와 JSON에 이 등급을 함께 기록한다.

## 계산 지표

### 모델 단독 지표

- 행 수, 정답 평균과 예측 평균
- 예측 표준편차, 최솟값과 최댓값
- Brier Score
- fold 정답 평균을 기준으로 한 로컬 Brier Skill Score. 비공개 평가 자료의 평균을
  쓰는 공식 점수와 같은 값으로 해석하지 않음
- ROC AUC와 log loss
- 10분위 calibration 표
- Expected Calibration Error는 보조 진단으로만 기록

### 시간·구간 진단

자료에 존재하는 열만 사용해 다음을 계산한다.

- 검증 시즌과 월
- `game_type`
- count state
- hand matchup
- base-out state
- 투수·타자 known/OOV

구간별 행 수, 정답 평균, 예측 평균, Brier와 기준 모델 대비 paired delta를 기록한다.
행이 5,000개 미만인 구간은 수치는 남기되 다음 실험을 결정하는 하드 근거로 쓰지
않는다.

### 모델 간 지표

같은 행에서만 다음을 계산한다.

- 예측 확률 Pearson 상관
- 행별 Brier 손실 Pearson 상관
- signed residual 상관
- 두 모델 평균의 Brier
- 후보 모델 비중을 `0.25`, `0.50`, `0.75`로 고정하고 나머지를 기준 모델에 둔
  paired Brier
- 후보와 기준 모델의 행별 손실 차이 평균 및 95% 신뢰구간

신뢰구간은 행을 독립 표본으로 가장하는 단순 bootstrap 대신 `검증 시즌 × 월` 블록을
seed `3407`로 2,000번 재표집해 계산한다. 독립 블록이 6개 미만이면 신뢰구간을
만들지 않고 이유를 기록한다.

## 기준 모델

직접 비교 그룹마다 기준 모델을 명시한다. Stage C의 seed 3407 TabM이 같은 행에
있으면 이를 기본 기준으로 사용한다. 없으면 규칙 준수 후보 중 사전에 지정된 anchor를
사용하며, 실행 중 가장 점수가 좋은 모델로 기준을 바꾸지 않는다.

## 진단 판정

감사 결과는 자동으로 제출 후보를 승인하지 않는다. 다음 중 하나의 연구 방향만
선택한다.

### `RECENCY_WEIGHTING`

다음 조건을 모두 만족할 때 선택한다.

- 주요 모델의 최신 fold 성능이 이전 fold보다 일관되게 좋거나 나쁨
- 월 또는 시즌에 따른 calibration 이동이 모델 간 공통으로 나타남
- 이질 모델의 잔차 상관이 높아 블렌딩 이득이 작음

다음 실험은 행 독립성을 유지하는 rolling-window와 train-season recency weight
비교로 제한한다.

### `DIVERSE_BLEND`

다음 조건을 모두 만족할 때 선택한다.

- 두 개 이상의 규칙 준수 모델이 같은 행에서 비교 가능함
- 최신 fold를 포함한 모든 확인 fold에서 사전 고정 평균이 단독 기준보다 개선됨
- 구간 최대 악화가 `0.00075` 이하임
- 격리 XGBoost가 아니라 규칙 준수 모델만으로 구성 가능함

### `STOP_AND_REFRAME`

최근 fold에서 재현되는 개선도, 안정적인 이질 잔차도 없으면 선택한다. 이 경우
파생변수나 calibration을 더 추가하지 않고 모델 입력과 시간 변화 가정부터 다시
설계한다.

판정 조건이 둘 이상 겹치면 `RECENCY_WEIGHTING`, `DIVERSE_BLEND`,
`STOP_AND_REFRAME` 순서로 고르지 않는다. 각 조건의 근거를 출력하고 최종 선택은
별도의 검토 단계에서 하나만 확정한다.

## 산출물

감사 실행은 새 디렉터리에 다음 파일만 만든다.

- `audit_summary.md`: 비교 가능성, 핵심 실패 원인과 다음 선택지
- `model_comparison.csv`: 모델·fold별 단독 지표
- `paired_comparison.csv`: 기준 대비 paired delta와 신뢰구간
- `segment_diagnostics.csv`: 월과 구간별 지표
- `correlation_matrix.csv`: 예측·손실·잔차 상관
- `calibration_deciles.csv`: 분위별 실제율과 평균 예측
- `artifact_inventory.json`: 입력 SHA-256, 역할과 검증 결과
- `next_experiment.json`: 판정 근거와 선택 가능한 다음 방향
- `oof_reset_audit_results.zip`: 위 작은 결과만 포함한 전달 파일

원본 OOF, 학습 데이터, 모델, checkpoint와 제출 파일은 결과 ZIP에 넣지 않는다.

## 실행과 자원

감사는 CPU 전용이며 새 학습이나 추론을 하지 않는다. 사용자가 기존 ZIP을 준비해
한 명령 또는 한 셀로 실행한다. 전체 OOF를 읽으므로 예상 시간은 5~15분이고, 필요한
메모리는 입력 규모에 따라 약 2~6GB다.

Codex는 코드 작성, 합성 fixture 테스트, 정적 검사와 작은 ZIP 테스트만 수행한다.
공식 전체 OOF 감사는 사용자가 실행하고 `oof_reset_audit_results.zip` 하나를
전달한다.

재실행 시 기존 결과를 덮어쓰지 않고 새 실행 ID 디렉터리를 만든다. 입력이 부족하거나
손상되면 부분 결론을 성공으로 저장하지 않고 `AUDIT_ERROR`와 정확한 파일 역할을
출력한다.

## 테스트 범위

- ZIP traversal, symlink, 중복 member와 비정상 압축 비율 거부
- manifest와 예측 SHA-256 불일치 거부
- 중복 `row_id`, 정답 불일치, 비유한 확률과 범위 이탈 거부
- 행 순서를 바꿔도 paired 결과 동일
- 행 집합이 다르면 직접 비교 차단
- 격리 XGBoost가 blend와 next experiment 후보에 들어가지 않음
- Brier, BSS, 상관, calibration과 block interval의 정확값
- 입력 부족 시 `missing_evidence`와 비승인 판정
- 결과 ZIP에 허용된 작은 파일만 포함

## 성공 기준

감사는 다음 조건을 모두 만족해야 완료된다.

1. 입력한 모든 ZIP의 SHA-256과 판별 결과가 기록된다.
2. 직접 비교 수치는 전부 같은 fold와 전체 `row_id` 집합에서 계산된다.
3. 규칙 준수 결과와 격리 진단 결과가 산출물 전반에서 분리된다.
4. 기존 보고서 수치를 복사하지 않고 예측 행에서 지표를 다시 계산한다.
5. 다음 GPU 실험을 자동 승인하지 않고 근거가 있는 최대 세 방향만 제시한다.
6. 전달 ZIP만으로 결론과 누락 증거를 검토할 수 있다.

## 비목표

- 새 모델 학습 또는 전체 학습 데이터 로드
- 평가 데이터, 제출 예측 또는 Public 기반 가중치 사용
- 기존 모델 패키징이나 제출 ZIP 생성
- 모든 모델 계열의 재탐색
- 시각화 대시보드 또는 범용 실험 관리 프레임워크 구축
