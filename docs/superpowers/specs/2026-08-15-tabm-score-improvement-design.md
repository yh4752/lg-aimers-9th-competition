# TabM 점수 개선 설계

## 배경과 목표

첫 규칙 준수 TabM 제출은 Public `872.3920184667`을 기록했다. 현재 1위의 1,100점
초과와 비교하면 최소 `227.6079815333`점 차이다. 이 차이는 평균 성공률 Brier를
기준으로 최대 약 `0.00056902`의 절대 Brier 감소에 해당한다.

목표는 Public 점수에 맞춘 시행착오가 아니라 시간 전이 OOF에서 재현되는 Brier
개선을 찾는 것이다. 첫 목표는 900점대, 다음 목표는 1,000점 이상으로 둔다. 목표
점수는 연구 방향을 설명하는 기준일 뿐 후보의 가중치나 채택 여부를 정하지 않는다.

## 판단한 접근

### 채택: 기존 예측 재사용 후 단계적 확장

기존 Stage C의 seed별 시간 전이 예측을 먼저 조합해 앙상블 가능성을 비용 없이
판정한다. 통과한 경우에만 추가 seed 전체 학습을 수행한다. 이후 파생변수와 이질
모델 블렌딩을 각각 독립 단계로 검증한다.

이 방식은 이미 지불한 GPU 비용을 활용하고, 성능이 나지 않는 조합을 전체 학습하기
전에 중단할 수 있다.

### 기각: 동일 단일 모델 장시간 재학습

Stage 5에서 최대 43 epoch를 비교했지만 최적 checkpoint는 2 epoch였다. Stage C의
최근 fold도 seed별 최적 시점이 2~3 epoch였다. 최종 3 epoch 학습은 근거가 있으며,
epoch만 늘리는 실험은 과적합 가능성이 더 크다.

### 보류: 모델 계열 전면 재탐색

FT-Transformer와 TabNet sentinel은 같은 예산에서 TabM보다 낮았고, CatBoost와
XGBoost의 기존 Public도 TabM보다 낮았다. 계열 전면 재탐색은 독립적인 새 근거가
생길 때 진행하며 현재 GPU 예산의 첫 사용처로 삼지 않는다.

## 공통 검증 계약

- 모델 선택은 `2022→2023`, `2023→2024` 시간 전이 두 fold를 사용한다.
- 전처리, 범주 사전, 집계와 보정 상태는 각 fold의 학습 구간에서만 적합한다.
- 평가 행에서 만드는 특징은 같은 행의 값과 학습 데이터에서 고정한 lookup만 쓴다.
- 평가 데이터 전체의 평균, 빈도, 순위, 분위수, 행 순서와 이전 평가 행을 사용하지
  않는다.
- Public 점수로 가중치, seed, 파생변수 또는 보정 계수를 역선택하지 않는다.
- 모든 후보는 단독 행, 역순, 섞인 순서와 여러 batch 크기에서 같은 예측을 내야 한다.
- 두 fold의 `row_id`, 정답과 예측이 완전히 정렬된 경우에만 비교한다.

검증 행 수 가중 평균 Brier를 주 지표로 사용한다. 후보는 가중 평균을 최소
`0.00003` 낮추고 두 fold 중 어느 하나도 `0.00003`보다 많이 악화시키지 않아야 다음
단계로 승격한다. 개선량이 `0.00003` 미만이면 계산 오차나 seed 변동과 구분하기
어렵다고 보고 중단한다.

## 1단계: 기존 seed 앙상블 감사

### 입력

Stage C에 저장된 seed 42, 2026, 3407의 두 fold 예측과 공식 학습 데이터 정답을
사용한다. 새 모델을 학습하지 않는다.

### 사전 등록 조합

- seed 42 단일
- seed 2026 단일
- seed 3407 단일
- 세 seed 단순 평균
- seed 42와 3407의 1:1 평균

연속 최적화나 Public 기반 가중치 탐색은 하지 않는다. seed 42는 최근 fold 단독
Brier가 가장 낮고 seed 3407은 이전 fold 안정성이 가장 좋았기 때문에 1:1 후보를
포함한다.

### 승급과 중단

단순 평균 후보 중 하나가 공통 검증 계약을 통과하면 해당 구성만 전체 학습한다.
통과하지 못하면 현재 seed 3407 단일 모델을 유지하고 추가 seed GPU 학습을 생략한다.
세 모델 앙상블의 예상 추론 시간은 기존 단일 모델 약 12초의 세 배 수준으로, 공식
10분 제한에 충분한 여유가 있다. 실제 제출 전에는 L4 또는 T4 규모 검사를 다시 한다.

## 2단계: 행 단위 파생변수

앙상블 여부와 별개로 다음 네 묶음을 각각 단일 ablation으로 비교한다.

1. `count_context`: 볼·스트라이크 조합, 주자·아웃 조합
2. `pressure_context`: 이닝 구간, 점수 차 구간, 레버리지 구간의 행 단위 조합
3. `recent_trend`: 최근 1·3·5경기 성공률과 middle rate의 차이
4. `pitchmix_shape`: 구종 비율의 최댓값, 엔트로피와 비율 간 차이

구간 경계와 결측 처리값은 fold 학습 구간에서만 고정한다. 문자열 조합과 비율 차이처럼
상태가 필요 없는 특징도 평가 행 하나만으로 계산한다. 여러 묶음을 처음부터 합치지
않는다. 단일 ablation 중 공통 검증 계약을 통과한 특징만 합친 뒤 한 번 재검증한다.

선수별 target encoding, 투수·타자 pair 통계와 고차원 ID 조합은 희소성과 누출 위험이
커서 이번 단계에서 제외한다. 필요하면 별도 설계로 다룬다.

## 3단계: TabM과 트리 모델 블렌딩

기존 CatBoost/XGBoost Public 예측이나 평가 평균 이동 보정 모델을 그대로 쓰지 않는다.
동일한 두 시간 fold, 동일한 행 집합으로 새 규칙 준수 CatBoost OOF를 만든다. TabM과
CatBoost의 예측 상관과 잔차 상관을 먼저 기록한다.

사전 등록 가중치는 TabM 비중 `0.70`, `0.80`, `0.90`과 TabM 단독이다. 공통 검증
계약을 통과한 가중치가 있을 때만 전체 학습 모델을 만든다. CatBoost가 단독으로
TabM보다 낮더라도 오류 다양성으로 blend가 개선될 수 있지만, OOF 이득이 없으면
Public 제출로 확인하지 않고 중단한다.

## 4단계: 보정

앙상블과 파생변수를 확정한 뒤 마지막으로 검토한다. 기존 전역 temperature와
`game_type`별 보정은 평균 Brier를 낮췄지만 안정성 gate를 통과하지 못했으므로 그대로
재사용하지 않는다.

새 보정은 OOF만으로 적합한 전역 shrinkage 한 종류를 기준으로 시작한다. 모든 계수는
전체 학습을 마친 뒤 모델 파일과 함께 고정한다. 평가 데이터의 평균 확률이나 성공률에
맞추는 이동 보정은 금지한다.

## 실행 순서와 자원 사용

1. 기존 OOF 앙상블 감사: GPU 없음, 사용자가 전체 예측 자료로 실행
2. 파생변수 proxy: 승급 가능성이 있는 네 ablation만 GPU 실행
3. 두 fold 확인: proxy 승자만 전체 행으로 재검증
4. seed 전체 학습: 1단계 통과 구성만 실행
5. CatBoost OOF와 blend: TabM 결과가 고정된 뒤 실행
6. 보정 및 전체 학습: 모든 선택을 OOF에서 닫은 뒤 한 번 실행
7. 독립성·시간·메모리·패키지 gate: 새 후보마다 별도로 통과

각 장시간 실행은 checkpoint와 resume bundle을 남긴다. 실행이 끊겨도 완료된 epoch와
후보를 다시 시작하지 않는다. Codex는 코드와 작은 fixture 검증을 맡고, 공식 전체
자료 OOF와 GPU 학습은 사용자가 실행한다.

## 산출물

- 단계별 OOF Brier와 fold delta
- 후보별 예측 상관과 blend 기여도
- 선택·기각 이유가 포함된 작은 JSON
- 전체 학습 모델의 provenance와 SHA-256
- 독립성, 설치, 추론 시간과 메모리 evidence
- 모든 gate를 통과한 후보에 한해서만 생성되는 제출 ZIP

첫 작업은 기존 Stage C 예측만 읽는 seed 앙상블 감사 코드다. 이 감사가 끝나기 전에는
추가 GPU 학습이나 새 제출 파일을 만들지 않는다.
