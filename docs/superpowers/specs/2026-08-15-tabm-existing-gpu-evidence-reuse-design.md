# TabM 기존 GPU 증거 재사용 설계

## 목적

Kaggle GPU를 추가로 사용하지 않고 Version D TabM 후보를 최종 제출 패키지까지 검증한다. 새 학습이나 전체 규모 재추론은 하지 않는다. 기존 Tesla T4 실행 증거와 현재 제출 런타임의 가벼운 호환성 검사를 서로 다른 증거로 유지한 뒤, 둘이 같은 모델을 가리킬 때만 승인한다.

## 재사용할 증거

`tabm_hand_matchup_stage_D_review_delivery.zip`에 기록된 다음 결과를 GPU 실행 증거로 사용한다.

- 후보: seed 3407, 3 epochs, 공식 train 2019~2024 학습
- GPU: Tesla T4 1개
- 규모 검사: 245,789행, 11.939초
- 자원 사용량: GPU 약 0.97GB, RAM 약 4.09GB
- 행 독립성 최대 확률 차이: `2.9802322387695312e-08`
- 모델 구성 파일과 가중치의 SHA-256

증거를 재사용하려면 Stage D 번들의 모델 파일별 SHA-256과 현재 제출 후보의 모델 파일별 SHA-256이 모두 일치해야 한다. 후보 ID만 같거나 파일 이름만 같은 경우에는 승인하지 않는다.

## 현재 제출 코드 검사

GPU 규모 검사를 반복하는 대신 최종 `script.py`에 대해 다음 검사를 수행한다.

1. 공식 평가 환경과 같은 Python 3.11 계열에서 import와 5행 추론을 확인한다.
2. 공식 샘플 5행을 원래 순서, 역순, 고정 셔플, 서로 다른 배치 크기, 단일 행으로 예측한다.
3. 모든 경우의 예측이 허용 오차 `1e-6` 안에서 일치하는지 확인한다.
4. 전처리 상태와 범주 매핑, 수치 임베딩 경계, 모델 가중치가 실행 중 바뀌지 않는지 해시로 확인한다.
5. `script.py`, `requirements.txt`, `model/`만 최상위에 들어가고 결과가 `output/submission.csv`로 기록되는지 확인한다.
6. 공식 train에서 고정한 상태와 같은 행에서 계산한 `hand_matchup`만 사용하며, 평가 데이터 전체의 통계·빈도·순위·시차·집계를 사용하지 않는지 검사한다.

로컬 공식 `test.csv`는 5행뿐이므로 이 검사는 숨겨진 평가 데이터의 성능이나 분포를 주장하지 않는다. 대규모 실행시간과 GPU 메모리는 동일 모델에 묶인 기존 Stage D T4 증거로만 판단한다.

## 증거 결합과 승인 조건

승인 레코드는 다음 조건이 모두 참일 때만 생성한다.

- 모델 파일별 SHA-256과 결합 모델 SHA-256이 Stage D 및 현재 후보에서 동일하다.
- Stage D GPU 규모·자원·행 독립성 검사가 통과 상태다.
- 현재 최종 런타임의 Python 3.11 호환성, 5행 예측, 행 독립성, 출력 계약 검사가 통과한다.
- 현재 대회 정책 검토가 패키징 당일 기준으로 유효하다.
- requirements와 최종 런타임 SHA-256이 승인 레코드에 기록된다.
- 시간·메모리·패키지 크기가 공식 제한보다 작다.

최종 런타임의 모델 로딩 방식이나 전처리 의미가 Stage D와 다르다고 판정되면 기존 GPU 증거를 결합하지 않고 패키징을 중단한다. 누락된 값을 추정하거나 통과로 간주하지 않는다.

## 산출물

승인 후에만 패키저가 다음 구조의 ZIP을 한 번 생성한다.

```text
submit.zip
├── script.py
├── requirements.txt
└── model/
```

함께 생성되는 영수증에는 후보 ID, 정책 버전, 모델·런타임·어댑터 SHA-256, ZIP SHA-256과 크기를 기록한다. 제출 ZIP에는 검증 로그, 학습 데이터, 검증용 CSV, 옵티마이저 상태를 넣지 않는다.

## 실패 처리

해시 불일치, Python 3.11 실행 실패, 행 독립성 실패, 정책 검토 만료, 제출 구조 불일치 중 하나라도 발생하면 ZIP을 만들지 않는다. 기존 파일을 덮어쓰지 않으며 실패한 임시 ZIP은 삭제한다.

## 검증 범위

Codex는 정적 검사, 작은 공식 샘플 검사, 단위 테스트와 패키지 구조 검사를 실행한다. 전체 데이터 학습이나 GPU 재실행은 하지 않는다. 최종 ZIP은 승인 레코드와 현재 입력 해시가 일치한 뒤에만 생성한다.
