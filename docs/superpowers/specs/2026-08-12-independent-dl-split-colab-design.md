# 독립 DL 후보별 Colab 실행 설계

## 목적

무료 Colab GPU의 가변적인 사용 한도에 맞춰 독립 DL 캠페인을 모델 계열별로 나누고,
셀을 한 번 실행할 때 미완료 후보 하나만 학습한다. 사용자는 GPU를 다시 사용할 수
있을 때 같은 셀을 재실행하여 다음 후보 또는 중단된 후보를 이어간다.

## 범위

- 기존 캠페인 실행 함수에 모델 계열 선택과 실행 후보 수 제한을 추가한다.
- 기존 명령행 `run` 동작에 `--family`와 `--max-candidates`를 추가한다.
- `INDEPENDENT_DL_CAMPAIGN.ipynb`를 공통 준비, 상태 확인, 계열별 실행, 결과 요약
  셀로 재구성한다.
- 기존 캠페인 설정, 후보 순서, Drive 출력 구조, manifest 및 epoch checkpoint를
  그대로 사용한다.

여기서 최소화하는 것은 코드 변경 범위와 한 번의 Colab 실행 단위뿐이다. 실험의
모델 용량, 학습 길이, 입력 표현, seed, fold와 탐색 경계는 축소하지 않는다.

다음은 만들지 않는다.

- 모델 계열별 별도 설정 파일이나 별도 노트북
- 새로운 상태 머신 또는 checkpoint 형식
- 자동 제출 파일 생성
- 전체 데이터 학습을 포함한 Codex 측 장시간 실행

## 성능 탐색 범위 보존

계열 선택은 후보를 삭제하거나 작은 모델만 남기는 필터가 아니라 실행 스케줄러다.
기존 캠페인에 고정된 다음 범위를 모두 보존한다.

- TabM, MLP/ResNet, FT-Transformer와 TabR의 P1~P4 전체 용량
- `raw_typed`, `engineered`, `entity_context`, `trackman_augmented` 입력 표현 교차
- P3의 큰 모델과 최대 240 epoch, P4의 더 큰 모델과 최대 400 epoch
- 설정상 최고 용량이 최선일 때 등록되는 boundary expansion
- 살아남은 후보의 2021→2022, 2022→2023, 2023→2024 fold와 seed
  42·2026·3407 확인
- 연구용 TabICLv2 frontier 후보

`--max-candidates 1`은 한 번의 셀 실행에서 시도하는 후보 수만 제한한다. epoch,
모델 깊이·폭, feature 수, seed 수와 전체 후보 수를 제한하지 않는다. 무료 GPU의
OOM이나 시간 종료는 batch 축소와 checkpoint 재개 사유일 뿐 모델 계열 또는 큰
용량 후보의 기각 근거로 사용하지 않는다. 기존 patience와 사전 고정된 acceptance
규칙도 변경하지 않는다.

상태 확인 셀은 P3·P4, boundary expansion과 confirmation이 남아 있는지를 숨기지
않고 계열별 다음 후보와 전체 남은 후보 수를 함께 표시한다. 따라서 초기의 쉬운
후보만 실행하고 캠페인이 끝난 것처럼 보이는 상태를 허용하지 않는다.

## 실행 동작

공통 준비 셀은 Drive, 저장소, 패키지, 데이터와 GPU를 준비하지만 학습하지 않는다.
상태 확인 셀은 계열별 완료·실패·대기 후보와 다음 후보를 보여준다.

계열별 실행 셀은 `tabm`, `mlp_resnet`, `ft_transformer`, `tabr`, `tabicl_v2`로
나눈다. 각 셀은 해당 계열에서 기존 캠페인 우선순위상 가장 앞선 미완료 후보 하나만
실행하고 종료한다. 같은 셀을 재실행하면 유효하게 완료된 후보를 건너뛰고 다음 후보를
실행한다. `running` 상태로 중단됐거나 산출물 해시가 무효인 후보는 기존 복구 규칙에
따라 `pending`으로 돌아가 먼저 재개한다.

후보 하나가 정상적인 후보 실행 오류로 실패하면 실패를 기록하고 그 셀 실행은
종료한다. 같은 계열의 다음 후보는 이후 재실행에서 선택될 수 있다. 예상하지 못한
프로그램 오류는 숨기지 않고 traceback을 그대로 남긴다.

## 노트북 설명 계약

각 계열 셀 앞에는 한국어로 다음을 명시한다.

- 셀의 목적과 실행할 모델 계열
- 필요한 공통 준비와 입력 경로
- 후보 하나만 실행한다는 점
- 예상 시간이 모델과 GPU에 따라 수십 분에서 여러 시간일 수 있다는 점
- Drive checkpoint를 이용한 재실행 동작
- 정상 완료 시 확인할 문구와 결과 경로
- 오류 시 첫 traceback부터 전체 출력을 전달해야 한다는 점

TabICLv2는 기존과 같이 `research_only`이며 대회 제출 후보로 자동 승격하지 않는다.
어떤 셀도 제출 CSV나 ZIP을 생성하지 않는다.

## 검증

- 선택한 계열 외 후보가 실행되지 않는 작은 가짜 런타임 테스트
- 한 번의 호출에서 후보가 최대 하나만 실행되는 테스트
- 재실행 시 완료 후보를 건너뛰고 다음 후보가 선택되는 테스트
- 실패 후보 기록 후 다음 재실행이 다음 후보를 선택하는 테스트
- 명령행 옵션 전달 테스트
- 노트북 셀 순서, 계열별 명령, 한국어 실행 설명과 비제출 문구 정적 테스트
- P3·P4, boundary expansion과 다중 fold·seed 후보가 계열별 실행에서도 제거되지
  않는 계약 테스트

전체 데이터 전처리와 GPU 학습은 사용자가 Colab에서 실행한다. 구현 중에는 작은
fixture 테스트, 문법 검사와 노트북 JSON 검사만 수행한다.
