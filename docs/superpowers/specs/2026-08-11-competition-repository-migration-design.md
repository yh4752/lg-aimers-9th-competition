# LG Aimers 9th 대회 전용 저장소 이전 설계

## 목적

`LG_AIMERS_2026` 저장소에는 학습 대시보드, 강의 자료, ML 지식베이스와 대회
코드가 함께 있다. 새 비공개 저장소 `yh4752/lg-aimers-9th-competition`은 대회
코드, 사용자 실행용 Colab, 실험 기록과 작은 검증 근거만 관리하는 단일 진입점이
된다.

이번 이전은 기존 저장소의 대규모 리팩터링이 아니다. 검증된 자료를 선별 복사하고
새 저장소에서 확인한 뒤 기준 저장소를 전환한다. 기존 저장소와 Drive 산출물은
삭제하거나 이동하지 않는다.

## 저장소 경계

새 저장소의 초기 구조는 아래로 제한한다.

```text
.
├── README.md
├── AGENTS.md
├── pyproject.toml
├── .gitignore
├── docs/
│   ├── EXPERIMENT_CONTRACT.md
│   ├── ROADMAP.md
│   └── rounds/
├── src/                       # 이미 여러 실험이 공유하는 검증 코드
├── experiments/
├── notebooks/
├── reports/
│   ├── EXPERIMENT_LEDGER.md
│   ├── acceptances/
│   ├── rejections/
│   └── diagnostics/
└── tests/
```

- `README.md`는 현재 기준선, 진행 후보, 주요 결과와 실행 문서 링크를 보여주는
  사람용 대시보드다.
- `AGENTS.md`는 저장소 전체에 적용되는 짧고 강한 실행 가드레일이다.
- `docs/EXPERIMENT_CONTRACT.md`는 검증, 역할, 상태와 패키징 규칙의 현재
  진실원본이다.
- `docs/ROADMAP.md`는 다음 후보의 우선순위와 근거를 기록한다.
- `docs/rounds/`는 앞으로 완료하는 의사결정 단위의 가설, 검증, 결과와 다음
  판단을 기록한다. 기존 모델명인 R9 등의 이름은 바꾸지 않는다.
- `src/`는 R9와 calibration처럼 두 개 이상의 실험이 이미 공유하는 preflight,
  시간 검증과 행 독립성 코드만 둔다.
- `experiments/`는 재현하거나 이어서 탐색할 가치가 있는 코드만 둔다.
- `notebooks/`는 사용자가 위에서 아래로 실행할 수 있는 완결된 Colab만 둔다.
- `reports/`는 작은 판정 근거와 전체 실험 장부를 보관한다.
  `diagnostics/`는 수용이나 패키지 승인이 아닌 읽기 전용 분석 근거만 둔다.
- `tests/`는 합성 데이터, fixture, import와 정적 계약처럼 빠른 검증만 수행한다.

초기 이전에 필요하지 않은 추가 계층, 범용 프레임워크와 자동 문서 생성기는 만들지
않는다. `src/`에는 기존에 공유되는 코드만 옮기고 미래 후보를 예상한 추상화는
추가하지 않는다.

## 이전 범위

### 코드와 함께 이전

- 검증된 R9 시간 전이 기반과 독립 검증 코드
- calibration blending의 재현 가능한 코드와 완료된 판정
- XGBoost v3와 original preprocessing rescue의 재현 가능한 코드
- 현재도 재사용하는 데이터 preflight, 행 독립성 및 산출물 검증 코드
- 위 코드에 필요한 설정, 작은 fixture와 테스트
- 실제로 다시 실행할 가치가 있는 사용자용 Colab

### 기록만 이전

- FwFM standalone과 제한 블렌드의 기각 결론
- TabM residual의 기각 결론
- 완료된 CatBoost proxy 실험
- 대체된 세부 탐색과 구현 과정
- 기존 긴 설계에서 현재 판단에 필요한 가설, 수용 기준과 결론

### 이전하지 않음

- 학습 대시보드, 강의 노트, PDF와 수강 데이터
- 범용 ML 지식베이스와 로드맵
- 완료된 구현 계획, 리뷰 대화와 임시 디버깅 문서
- 대용량 원본 데이터, OOF, 모델과 제출 ZIP
- 동료 저장소의 전체 코드 및 보고서 복제
- 캐시, 가상환경, 임시 산출물과 중복 파일

## 기존 긴 설계와 가드레일

기존 `experiments/kyh/high_score/AGENTS.md`의 경쟁 관련 규칙은 새 루트
`AGENTS.md`로 축약해 옮긴다. 따라서 하위 폴더 위치와 관계없이 같은 규칙이
적용된다.

반드시 유지할 계약은 다음과 같다.

- 최우선 목표는 누출 없는 검증으로 확인한 성능 향상이다.
- 비용은 실행 순서와 자원 안내에 사용하며 비용만으로 후보를 제외하지 않는다.
- 한 후보의 실패로 독립 후보나 모델 계열 전체를 자동 종료하지 않는다.
- Codex는 코드, 정적 검사와 작은 합성 테스트를 담당한다.
- 사용자는 공식 데이터 전처리, 전체 OOF, CPU·GPU 학습, Colab 장시간 실행과
  제출 평가를 담당한다.
- 사용자 요청 없이 push, 노트북 변경·재생성, 패키징 또는 제출을 하지 않는다.
- acceptance evidence와 현재 산출물 해시가 모두 통과하기 전에는 제출 패키지를
  만들지 않는다.
- 테스트 및 제출 행은 다른 평가 행, 행 순서와 배치 크기에 독립적이어야 한다.
- 후보 설정과 선택 기준은 결과를 보기 전에 고정한다.

R9, FwFM, TabM, calibration과 XGBoost의 긴 설계 원문은 기존 저장소에 남긴다.
새 저장소에는 현재 운영에 필요한 내용과 최종 결론만 옮기며, 과거 원문을 현재
명령으로 취급하지 않는다. 이전 문서에 현재 상태와 충돌하는 표현이 있으면 완료된
실행 근거와 최신 판정을 우선한다.

## 실험 기록 계약

`reports/EXPERIMENT_LEDGER.md`는 모든 완료 실험의 시간순 색인이다. 각 항목은
최소한 다음을 포함한다.

- 실험 ID와 모델 계열
- 가설과 비교 대상
- 검증 프로토콜
- 핵심 Brier 및 필요한 segment 지표
- `accepted`, `rejected`, `failed`, `diagnostic` 중 판정
- 작은 Git 근거와 대용량 Drive 원본 위치
- Public 결과가 있을 때만 별도 Public 점수
- 다음 의사결정

서로 다른 검증 프로토콜의 점수를 하나의 순위표처럼 비교하지 않는다. README의
요약 표에도 프로토콜을 함께 표시한다. 설계만 끝난 후보나 실행하지 않은 후보는
완료 실험으로 기록하지 않는다.

Drive에는 대용량 산출물을 그대로 유지한다. Git 보고서는 논리 경로, 실행 ID와
SHA-256을 기록해 원본을 식별한다. 토큰, 인증 URL, 개인 마운트 정보와 원본 데이터는
커밋하지 않는다.

## 동료 저장소 활용

`castle9612/lg_aimers_9th`는 참고 원본이지 새 저장소의 기반 브랜치가 아니다.
다음 정보는 폭넓게 참고할 수 있다.

- R9 CatBoost 모델 계보와 시간 전이 검증
- forward 검증과 Public 피드백 기록 방식
- R25 TabM 잔차 보정, R32 분모 보정과 실패 실험의 결론
- 라운드별 Markdown 보고서와 제출 아카이브 해시 관리 방식

코드는 다음 실험에 실제로 필요한 기능만 선별한다. 이식 전에는 데이터 누출,
평가 행 독립성, 현재 대회 규정, 입력 스키마와 재현성을 검토한다. 가져온 코드나
결론에는 출처 저장소와 관련 경로를 기록한다. 동료의 전체 스크립트, 산출물과 제출
아카이브는 복사하지 않는다.

## 이전 순서와 전환

1. 새 저장소의 문서, 루트 가드레일과 장부를 먼저 만든다.
2. 작은 acceptance와 rejection 근거를 복사하고 해시 및 JSON을 검사한다.
3. 이전 대상 코드를 기능 단위로 복사하되 기존 저장소는 수정하지 않는다.
4. 경로와 import를 새 구조에 맞춘 뒤 작은 테스트를 실행한다.
5. Colab은 즉시 재작성하지 않는다. 필요한 노트북만 별도 승인 후 새 경로로
   옮기고 결정적 생성 여부를 확인한다.
6. 새 저장소의 README, 장부, CLI와 테스트가 일관된지 확인한다.
7. 사용자가 결과를 확인한 뒤에만 새 저장소를 이후 작업 기준으로 선언한다.

어느 단계에서도 기존 저장소나 Drive 파일을 삭제하지 않는다. 문제가 발견되면 새
저장소 변경만 되돌리거나 보류할 수 있으며 기존 실행 경로는 그대로 남는다.

## 검증과 완료 기준

초기 이전은 다음 조건을 모두 만족하면 완료다.

- 루트 README에서 현재 기준선, 완료 실험, 다음 후보와 실행 문서에 접근할 수 있다.
- 루트 `AGENTS.md`와 실험 계약이 역할, 시간 누출, push, 노트북, 패키징 경계를
  명확히 강제한다.
- R9, FwFM, TabM, calibration, XGBoost v3와 rescue의 최종 판정이 장부에 있다.
- 작은 acceptance와 rejection JSON이 유효하며 장부 링크가 끊기지 않는다.
- 이전한 Python 코드가 새 저장소 경로에서 import되고 빠른 테스트가 통과한다.
- 원본 데이터, 대용량 OOF, 모델, ZIP과 비밀 정보가 Git에 포함되지 않는다.
- 기존 저장소와 Drive 산출물이 변경되지 않는다.
- 동료 저장소에서 가져온 내용은 출처와 검토 범위를 추적할 수 있다.

전체 과거 코드의 완전한 이전, 모든 Colab의 통합, 자동 제출, 실험 웹 대시보드와
동료 저장소 전체 병합은 초기 완료 기준에 포함하지 않는다.
