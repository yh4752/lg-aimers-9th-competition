# DL 주력·ML 공존 포트폴리오 설계

## 목적

현재 최고 CatBoost와 XGBoost를 버리지 않으면서 다음 주력 연구를 독립 DL로
전환한다. 한 번의 제한된 DL 실패나 ML의 단기 개선 가능성 때문에 연구 방향이
다시 ML 미세 조정에만 머무르지 않도록 저장소 규칙과 로드맵에 최소한의 영구
가드레일을 둔다.

리더보드 점수만으로 상위권 모델 계열을 단정하지 않는다. 다만 현재 최고점과의 큰
격차는 기존 ML의 작은 변형만 반복하지 않고 새로운 표현력을 넓게 탐색해야 한다는
근거로 사용한다.

## 고정 전략

주력 순서는 다음과 같다.

1. 독립 DL 탐색
2. 유망 DL 후보의 충분한 학습과 DL 내부 앙상블
3. 정렬된 OOF를 사용한 ML+DL 앙상블

CatBoost와 XGBoost는 폐기하지 않는다. 현재 강한 기준선, 특징 연구의 비교 대상과
최종 앙상블 축으로 유지한다. ML 단독 미세 조정은 독립 DL 준비나 사용자 GPU
실행을 지연시키지 않는 보조 트랙으로만 진행한다.

기존 `TabM residual` 기각은 해당 잔차형 구성의 판정이다. 독립 TabM이나 다른 DL
구조, DL 계열 전체의 실패로 확대 해석하지 않는다. 대회 규정 위반, 시간 누출,
데이터 손상과 유효하지 않은 산출물 위험이 없다면 width, depth, epoch, seed,
학습 시간과 GPU 사용량을 비용만으로 사전 제한하지 않는다.

## 탐색 단계

초기 단계에서는 서로 다른 독립 DL 구조와 넓은 용량·최적화 범위를 빠르게 비교한다.
트리 예측을 입력으로 강제하지 않으며, 독립 모델로서 새로운 신호를 찾는다.

초기 후보 모두에게 다중 seed, 장기 체크포인트와 완전한 앙상블 증거를 요구하지
않는다. 유망 후보에만 충분한 학습, 여러 seed와 필요한 중단 복구를 적용한다.
최종 비교·앙상블 단계에 진입한 후보만 동일 행·동일 검증 프로토콜의 OOF와 트리
모델 대비 오차 다양성을 확인한다.

단독 DL 점수가 현재 최고 ML보다 낮아도 오차 다양성이 충분하면 앙상블 후보로
유지할 수 있다. 최종 선택은 단독 성능과 앙상블 기여도를 함께 사용한다.

## 저장소 변경 범위

- `AGENTS.md`: DL 주력, ML 공존, 우선순위와 비제한 탐색 원칙을 짧게 추가한다.
- `docs/ROADMAP.md`: 독립 DL 탐색에서 ML+DL 앙상블까지의 실행 순서를 현재 다음
  순서로 교체한다.
- `tests/test_repository_contract.py`: 핵심 방향이 삭제되거나 ML 단독 우선으로
  되돌아가는 것을 감지하는 계약 테스트 하나를 추가한다.

`docs/EXPERIMENT_CONTRACT.md`의 누출 방지, 실행 소유권, acceptance와 패키징
규칙은 이미 충분하므로 수정하지 않는다.

## 명시적 제외

- 새 상태 JSON이나 별도 체크리스트 문서
- 실험 오케스트레이터나 자동화 시스템
- 구체적인 DL 모델 목록의 영구 고정
- 모든 초기 후보의 다중 seed와 체크포인트 의무
- 독립 DL 시작 전 CatBoost·XGBoost OOF 정렬 의무
- 이번 변경에서의 모델 코드, Colab 또는 제출 패키지 생성

## 검증 기준

- 기존 저장소 계약 테스트가 모두 통과한다.
- 새 테스트가 `독립 DL → DL 앙상블 → ML+DL 앙상블` 순서, ML 유지, 제한된
  `TabM residual` 실패의 비확대 해석을 확인한다.
- 변경은 `AGENTS.md`, `docs/ROADMAP.md`, 테스트 한 파일로 제한된다.
- 대용량 데이터, OOF, 모델, ZIP과 노트북은 변경하지 않는다.
