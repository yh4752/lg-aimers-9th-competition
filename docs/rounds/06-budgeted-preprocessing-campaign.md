# 예산 제한 전처리 캠페인: Stage 1~5

## 목표

T4 GPU 2장과 Kaggle Save Version 단위의 실행 제약 안에서 모델 계열과 전처리를
무작정 전수 탐색하지 않고 단계적으로 줄인다. 모든 변환은 학습 구간에서만 fit하고,
2023 또는 2024 검증 행에는 고정된 상태를 적용한다. 내부 선택 지표는 낮을수록 좋은
Brier Score다.

최종 질문은 다음과 같다.

- 이 데이터에서 전처리 연구를 이어 갈 대표 DL 모델은 무엇인가?
- 단순 변환, 과거 집계와 행 내부 상호작용 중 실제로 재현되는 개선은 무엇인가?
- 개선이 다른 시간 전이, 전체 학습 행과 사전 지정 segment에서도 유지되는가?

## 실행 프로토콜

탐색 단계는 2023년까지 학습한 400,000행의 결정론적 표본과 2024년 253,507행을
사용했다. 안정성 확인에는 2022→2023 전이의 400,000행 학습 표본과 245,525행
검증 자료를 추가했다. 최종 확인은 2023년까지의 전체 학습 행 1,221,585개와
2024년 검증 행 253,507개를 사용했다. 모든 실행의 seed는 42다.

Stage별 역할은 다음과 같다.

1. 대표 DL 모델과 TabNet 누락 방지 후보를 비교한다.
2. 대표 DL에서 수치 변환과 투수·타자 평활화를 단일 ablation으로 비교한다.
3. 과거 집계, 결측 표시와 행 내부 상호작용을 대표 DL과 CatBoost에서 비교한다.
4. 승격 후보를 2022→2023 전이와 CatBoost 전체 학습으로 다시 확인한다.
5. 대표 DL의 기본 전처리와 승격 후보를 전체 학습 행에서 최종 비교한다.

평가 데이터의 다른 행, 행 순서, 배치 크기나 평가 데이터에서 계산한 통계는 피처
생성에 사용하지 않았다.

## Stage 1: 대표 모델 선별

| 후보 | Brier | 판정 |
|---|---:|---|
| CatBoost `tree_native` | `0.2482911111` | 별도 트리 기준선 |
| TabM P2 | `0.2485090500` | 대표 DL로 선택 |
| FT-Transformer P2 | `0.2489329045` | 탈락 |
| TabNet sentinel | `0.2536153169` | 추천하지 않음 |

TabM P2는 비교한 DL 중 Brier가 가장 낮아 이후 DL 전처리 연구의 대표 모델로
선택됐다. TabNet은 대표 DL과의 차이, blend 및 OOV 기준을 충족하지 못했다. 이
결과는 모든 가능한 TabNet을 부정하는 결론이 아니라, 사전 등록한 sentinel 구성을
추가 승격하지 않는다는 뜻이다.

## Stage 2: 수치 변환과 평활화

| TabM 전처리 | Brier | 기본 대비 delta |
|---|---:|---:|
| 기본 `dl_standard` | `0.2485090500` | `0` |
| 선택적 Yeo-Johnson | `0.2485158194` | `+0.0000067694` |
| 타자 평활화 `k=250` | `0.2485206870` | `+0.0000116370` |
| 투수 평활화 `k=100` | `0.2485293272` | `+0.0000202772` |

세 후보 모두 기본 전처리를 이기지 못했다. 일반적으로 유용한 정규화나 평활화라도
이 TabM 구성에서는 자동으로 개선되지 않으므로 최종 전처리에 넣지 않았다.

## Stage 3: 집계·결측·상호작용 ablation

### TabM

| 후보 | Brier | 기본 대비 delta |
|---|---:|---:|
| `hand_matchup` | `0.2483636748` | `-0.0001453752` |
| `asof_count_log1p` | `0.2484952890` | `-0.0000137610` |
| `grouped_recent_missing` | `0.2485291946` | `+0.0000201447` |
| `id_frequency_log1p` | `0.2486287267` | `+0.0001196767` |

### CatBoost

| 후보 | Brier | `tree_native` 대비 delta |
|---|---:|---:|
| `hand_matchup` | `0.2481449493` | `-0.0001461618` |
| 투수 평활화 `k=100` | `0.2482289817` | `-0.0000621294` |
| 타자 평활화 `k=250` | `0.2482519992` | `-0.0000391119` |
| ID 빈도와 OOV | `0.2483135619` | `+0.0000224508` |

`hand_matchup`은 `pitcher_hand`와 `batter_hand`를 같은 행 안에서 결합한 범주형
피처다. TabM과 CatBoost 모두에서 사전 승격 기준을 넘긴 유일한 후보였다.

초기 TabM용 `entity_frequency_and_oov` 구성은 학습 행에서 항상 0인 OOV 열을
만들었다. Piecewise-linear embedding이 이 상수 열에 거의 0인 폭의 bin을 만든 뒤,
검증 행의 OOV 값 1을 변환하면서 float32 overflow와 NaN이 발생했다. FP32 재실행도
같은 원인으로 실패했으므로 OOV 열을 제거하고 학습 가능한 `id_frequency_log1p`로
교체했다. 교체 후보는 정상 완료했지만 성능이 나빠 최종 승격하지 않았다.

## Stage 4: 시간 안정성과 교차 모델 확인

| 모델·검증 | 기본 Brier | `hand_matchup` Brier | delta |
|---|---:|---:|---:|
| TabM, 2022→2023 proxy | `0.2504765794` | `0.2502313569` | `-0.0002452226` |
| TabM, 2023→2024 proxy | `0.2485090500` | `0.2483636748` | `-0.0001453752` |
| CatBoost, 2022→2023 proxy | `0.2513645047` | `0.2513053178` | `-0.0000591869` |
| CatBoost, 2023→2024 full | `0.2480887455` | `0.2480060989` | `-0.0000826466` |

TabM에서는 두 시간 전이 모두 개선됐고 검증 행 수로 가중한 delta는
`-0.0001945004`였다. CatBoost에서도 방향은 일관됐지만 개선 폭이 작아
`model_specific`으로 보관했다.

## Stage 5: 전체 학습 행 최종 확인

기본 TabM과 `hand_matchup` TabM은 동일한 전체 학습 행과 검증 행을 사용했다.
두 실행이 모두 포함하는 43 epoch 범위에서 최적 checkpoint를 비교했다.

| 후보 | Brier | 최적 epoch | 완료 epoch | 실행 시간 |
|---|---:|---:|---:|---:|
| 기본 TabM | `0.2483070113` | 3 | 44 | 4,086초 |
| TabM + `hand_matchup` | `0.2480974092` | 2 | 43 | 4,303초 |

전체 delta는 `-0.0002096021`이다. 253,507개 예측 행의 ID는 모두 고유했고,
저장된 예측으로 Brier를 다시 계산한 값도 보고서와 일치했다.

| Segment | 기본 Brier | `hand_matchup` Brier | delta |
|---|---:|---:|---:|
| 타자 ID known | `0.2483439467` | `0.2481510503` | `-0.0001928963` |
| 타자 ID OOV | `0.2479469921` | `0.2475745537` | `-0.0003724385` |
| `game_type=F` | `0.2479499812` | `0.2477397608` | `-0.0002102204` |
| `game_type=R` | `0.2483549515` | `0.2481454323` | `-0.0002095191` |
| 투수 ID known | `0.2482562408` | `0.2480502089` | `-0.0002060319` |
| 투수 ID OOV | `0.2485118752` | `0.2482878668` | `-0.0002240084` |

사전에 확인한 모든 segment에서 Brier가 낮아졌으며 최대 delta도 음수였다.

## 최종 판정

- TabM의 승인 전처리는 `dl_standard + hand_matchup`으로 확정한다.
- CatBoost의 `hand_matchup`은 작지만 일관된 개선이 있어 모델별 후보로 보관한다.
- 선택적 Yeo-Johnson, 단독 평활화, 과거 횟수, ID 빈도와 결측 표시를 TabM의 공통
  기본 전처리에 추가하지 않는다.
- TabNet sentinel은 추천하지 않는다.
- 이 결론은 전처리 캠페인의 종료이며 최종 제출 후보 승인을 의미하지 않는다.

`hand_matchup`은 각 행의 `pitcher_hand`와 `batter_hand`만 결합한다. 평가 자료
전체의 빈도, 평균, 정답이나 다른 평가 행을 사용하지 않으므로 피처 자체는 평가
샘플 독립 원칙을 지킨다. 최종 모델은 별도로 행 단독 추론, 행 순서 변경과 배치 크기
변경 불변성 검사를 통과해야 한다.

## 한계와 다음 결정

탐색 및 최종 확인 seed가 42 하나이므로 개선의 seed 안정성은 이후 모델 캠페인에서
확인해야 한다. `hand_matchup`을 기존 `engineered` feature view 전체와 같은 것으로
취급하면 다른 피처의 효과가 섞이므로, 다음 모델 비교에서는 이 단일 피처를 승인된
TabM 기준 전처리로 명시적으로 연결한다.

이후에는 독립 DL 결과와 결합해 모델 계열을 선택하고, 다중 seed, CatBoost와의
앙상블 가치, 평가 행 독립성을 순서대로 확인한다.

## 산출물 무결성

대용량 예측과 resume ZIP은 Git에 저장하지 않는다. 최종 검토 시 확인한 로컬
산출물의 SHA-256은 다음과 같다.

- Stage 5 review bundle:
  `314218a959a70c4cc7b35bae0943e2cf57aac2770fb33a204c871044193e855e`
- Stage 5 resume bundle:
  `4fdd77f9bf450de1b20832b98d0f9462e5b62ca8c6ba2ad83e9c9a1cc7c219e5`
- Resume 내부 campaign manifest:
  `a3255e7405fbb4ea75d7cc903754fa16f07921852555d2204d5724b373dbb9a1`

검토 당시 review bundle의 9개 기록 파일과 resume bundle의 98개 파일 해시가 모두
일치했고, manifest의 24개 작업이 모두 `completed`였다. 상태 JSON에는 이전 복구
과정의 `incomplete_stage=3`과 완료된 작업명이 `pending_jobs`에 남아 있지만,
manifest, 실제 산출물과 `completed_stage=5`가 완료를 증명한다. 이 값은 후속 실행
결정에 사용하지 않는다.
